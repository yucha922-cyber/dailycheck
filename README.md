# サロン日次業務チェックシステム

営業時間内（例 11:00〜20:00）に業務を終えて帰宅するための、
**Googleスプレッドシート＋Google Apps Script（GAS）** による日次チェックの仕組みです。

**「各業務マスター」を編集すれば、その場で「今日のチェック」が変わる** ——
これがこの仕組みの中心です。

---

## 0. 今回の修正点（v2.0）

> ご指摘のとおり、v1 はマスターを編集しても「今日のチェック」に反映されない状態でした。
> 原因と対処は次のとおりです。

| # | 原因 | 対処（v2.0） |
|---|---|---|
| 1 | コードが `業務マスタ` `本日のチェック` `日次ログ` という**別名のタブ**を探していた。お使いのシートは `各業務マスター` `今日のチェック` `履歴` `設定` なので、**別のタブを新規作成して**そちらで動いていた | タブ名を**別名込みで自動判別**。既にあるタブを見つけたら**それを使う**（新しいタブを作らない） |
| 2 | 列を「A列＝ID、B列＝区分…」と**位置で決め打ち**していた。既存シートの列並びが違うと読めない | 列は**見出しの文字で自動判別**。足りない列だけ右端に追加（既存の列・データは変更しない） |
| 3 | 反映は**インストール型 onEdit トリガー**が前提。これを一度も実行していないと、マスターを直しても何も起きない | 未設定を検出する **🩺 動作チェック（診断）** を追加。`onOpen` でも当日分を作り直すよう二重化 |
| 4 | 店舗名・営業時間などが**コードの中**にあり、変更しづらかった | **`設定` タブ**から変更できるように（コードを触らずに運用できる） |
| 5 | 新しい行を足すと「有効」列が未チェック（＝FALSE）で、**追加した業務が出てこなかった** | 区分・頻度・有効などの**空欄を自動補完**。行を足すだけで今日のチェックに出る |

動作は自動テストで確認済みです（`npm test` → 55件）。

## 1. 使うタブ（お使いのシートのまま）

| タブ | 役割 |
|---|---|
| `各業務マスター` | **すべての起点**。業務・頻度・目安時間・必須/有効を編集 |
| `今日のチェック` | 今日やる業務だけが自動で並ぶ。✓ を付けるだけ |
| `履歴` | 完了の記録（集計・本部集約の元データ。基本さわらない） |
| `設定` | 店舗名・営業時間・通知先・本部集約ID など |

`ダッシュボード` は任意です（`設定` の「ダッシュボードを使う」を TRUE にしたときだけ作成）。

> タブ名が多少違っても動きます（例：`業務マスター` `本日のチェック` `日次ログ` `Settings` など）。
> 見つからないタブだけ新規作成します。

## 2. 導入手順（5分）

1. スプレッドシートで **拡張機能 → Apps Script** を開く
2. `dist/DailyCheck.gs` の中身を**まるごとコピー**して、`コード.gs` に貼り付け → 保存
   （分割して管理したい場合は `apps-script/` の各ファイルを同名で作成してもOK）
3. スプレッドシートに戻って**再読み込み** → 上部に **🌸 サロン業務** メニューが出る
4. **🌸 サロン業務 → 🏗 初期セットアップ**（初回のみ権限承認 → 許可）
5. **🌸 サロン業務 → ⏰ 自動化トリガーを設定** ← ★これで「マスター編集の即反映」が有効に
6. **🌸 サロン業務 → 🩺 動作チェック（診断）** で全部 ✅ になっていれば完了

詳細は [`docs/01_導入手順.md`](docs/01_導入手順.md)。

## 3. マスターを編集 → 今日のチェックに反映される流れ

```
各業務マスター を編集
   ↓（onEdit トリガーが検知）
空欄を自動補完（ID採番／頻度＝毎日／有効＝ON）
   ↓
今日の日付で「頻度」を判定 → 今日やる業務だけ抽出
   ↓
今日のチェック を作り直す（付けた✓・担当・メモは保持）
   ↓
✓ を付けると 履歴 に自動記録
```

反映されるのは **業務の追加・削除・名称変更・頻度変更・有効ON/OFF・目安時間・備考** すべてです。

### 頻度の書き方

| 書き方 | 出るタイミング |
|---|---|
| `毎日` / `毎回` /（空欄） | 毎日 |
| `平日` | 月〜金 |
| `土日` | 土・日 |
| `月` `火` … `日` | その曜日だけ（複数は `月,木` `月水金`） |
| `月末` | 月末日だけ |
| `毎月15日` | 毎月15日（複数は `1日,15日`） |

詳細は [`docs/04_頻度と自動生成.md`](docs/04_頻度と自動生成.md)。

## 4. 毎日の使い方

- **開店前**：`今日のチェック` を開いて、清掃・カルテ準備などを ✓
- **営業中**：39メール・SATTOU入力などは、やった時点で ✓
- **閉店前**：売上確認・現金確認・事業計画更新などを ✓
- 上部に「完了 ○/○（○%）」がリアルタイム表示
- 1日の終わりは自動で確定（既定 20:30）。手動なら **✅ 今日の分を確定**

運用の詳細は [`docs/03_運用フロー.md`](docs/03_運用フロー.md)。

---

## 5. うまく動かないときは

まず **🩺 動作チェック（診断）** を実行してください。次を自動で点検します。

- どのタブを使っているか（別タブを作ってしまっていないか）
- マスターの列をどう認識したか
- 今日の対象が何件か／画面と一致しているか
- 自動化トリガーが入っているか ← **反映されない原因の第1位**
- 履歴に今日の記録が何件あるか

---

## 6. 多店舗への展開

- 各店舗は**同じコード**。変えるのは各店の `設定` タブだけ
- 本部用スプレッドシートを1つ用意し、そのIDを各店の `設定` に入力
- 毎晩、各店から**その日1行のサマリ**が本部の `店舗別サマリ` に自動で集まる

詳細は [`docs/02_マルチ店舗展開.md`](docs/02_マルチ店舗展開.md)。

## ファイル構成

```
dist/
  DailyCheck.gs        ← ★これ1つを貼り付ければ導入完了（自動生成）
apps-script/           ← 開発用の分割ソース
  Config.gs            タブ名・列見出しの別名定義／初期データ
  Common.gs            タブと列の自動判別・日付・頻度判定
  Settings.gs          「設定」タブの読み書き
  Master.gs            「各業務マスター」の整形と読み取り
  Checklist.gs         「今日のチェック」の生成・編集検知・確定
  History.gs           「履歴」への upsert と集計
  Dashboard.gs         ダッシュボード（任意）
  Diagnostics.gs       動作チェック（診断）
  Menu.gs / Triggers.gs / Setup.gs / CentralSync.gs
test/
  run.js               GASをNode上で実行して挙動を検証（npm test）
  gas-mock.js          スプレッドシートAPIのモック
tools/
  build.js             dist/DailyCheck.gs を生成（npm run build）
docs/
  01_導入手順.md / 02_マルチ店舗展開.md / 03_運用フロー.md
  04_頻度と自動生成.md / 05_既存シートへの反映.md
```
