# サロン日次業務チェックシステム（叩き台）

営業時間内（11:00〜20:00）に業務を終えて帰宅するための、
**スプレッドシート＋Google Apps Script（GAS）** による日次チェックの仕組みです。

- 毎日「本日のチェック」画面のチェックボックスを ON にしていくだけ
- 完了状況は自動で履歴（日次ログ）に記録
- 「ダッシュボード」で本日の完了率・区分別進捗・未完了・7日間の推移を見える化
- 将来は本部の集約シートへ各店舗の1行サマリを送信 → **100店舗を一元管理**

---

## 0. まず結論：どのアプリを使うか

| 用途 | 使うもの | 理由 |
|---|---|---|
| 日々のチェック・記録・集計 | **Googleスプレッドシート** | 既にお使い。無料・共有が簡単・スマホでも開ける |
| 自動化（記録・リセット・集計・通知・本部送信） | **Google Apps Script（GAS）** | スプレッドシートに標準で付属。追加費用ゼロ |
| 未完了アラート | **Gmail（GASから送信）** | 追加ツール不要 |
| 100店舗の一元管理 | **本部用スプレッドシート1つ**（＋各店GAS） | 特別なシステム不要で始められる |

> ポイント：新しいアプリを増やさず、**今のスプレッドシートの中だけ**で完結します。
> 「アプリ選定で悩む」段階を飛ばして、すぐ運用に入れます。

---

## 1. これは何をするコードか

このリポジトリの `apps-script/` は、そのまま**あなたのスプレッドシートを操作するプログラム**です。
実行すると、スプレッドシート内に次の4シートを自動生成・自動更新します。

| シート | 役割 |
|---|---|
| `業務マスタ` | **すべての起点**。業務の一覧・頻度（曜日）・目安時間・必須/任意を編集 |
| `本日の対象（自動）` | ★**関数だけ**でマスタから今日の業務を自動抽出（曜日判定つき） |
| `本日のチェック` | 毎日ここでチェック。ON にすると完了時刻が自動入力される |
| `ダッシュボード` | 完了率・区分別・未完了・7日推移・想定作業時間 vs 目標 |
| `日次ログ` | 完了履歴（集計・本部集約の元データ。基本さわらない） |

### マスタ更新 → 今日のチェックが自動で変わる

`業務マスタ` の **頻度** 列に次のように書くだけで、その日に出す業務が自動で切り替わります。

| 頻度の書き方 | 表示されるタイミング |
|---|---|
| `毎日` | 毎日 |
| `毎回` | 毎日（施術ごとに随時こなす業務） |
| `月` `火` … `日` | その曜日だけ（複数は `月,木` `月水金`） |

> 今日が月曜なら「毎日・毎回・月」を含む業務だけ、火曜なら「毎日・毎回・火」だけが自動表示。
> **業務マスタを直すだけで100店舗すべての「今日のチェック」が変わります**。
> 詳細・数式は [`docs/04_頻度と自動生成.md`](docs/04_頻度と自動生成.md)。

業務は以下の初期セットで登録されます（あとから自由に編集可）。

```
開店前 : 清掃 / カルテ準備
営業中 : カルテ記入 / 39メール / 口コミ返信 / SATTOU入力 / 前日リマインド / ブログ作成
閉店前 : 売上確認 / 現金確認 / 事業計画更新 / カルテスクリプト（＋曜日指定の例：週次棚卸し=月）
```

## 2. 導入手順（最短5分）

> このコードから直接あなたのスプレッドシートを編集する方法は2通りあります。
> **まずは A（コピペ）で十分**です。慣れてきたら B（clasp）を検討してください。

### A. コピペで導入（推奨・初回向け）
1. 対象のスプレッドシートを開く
2. メニュー **拡張機能 → Apps Script** を開く
3. `apps-script/` の中の各 `.gs` の中身を、Apps Script エディタに同名ファイルで貼り付け
   （`appsscript.json` はプロジェクトの設定＞「マニフェスト ファイルをエディタで表示」をONにすると編集できます）
4. `Config.gs` の `STORE_ID` / `STORE_NAME` を自店の値に変更して保存
5. スプレッドシートに戻り、**再読み込み**。上部に「🌸 サロン業務」メニューが出る
6. メニュー **🏗 初期セットアップ** を実行（初回だけ権限承認が出ます → 許可）
7. メニュー **⏰ 自動化トリガーを設定** を実行

これで完成です。詳細は [`docs/01_導入手順.md`](docs/01_導入手順.md)。

### B. コードから流し込み（clasp・上級/多店舗向け）
リポジトリのコードを CLI で直接スプレッドシートへ反映できます。
100店舗へ同じコードを配る運用に向いています。手順は [`docs/02_マルチ店舗展開.md`](docs/02_マルチ店舗展開.md)。

## 3. 毎日の使い方

- **開店前**：「本日のチェック」を開き、清掃・カルテ準備を実施したら ✓
- **営業中**：39メール・SATTOU入力などは、やった時点で ✓（施術の合間に）
- **閉店前**：売上確認・現金確認・事業計画更新などを ✓
- 上部に「完了 ○/○（○%）」がリアルタイム表示
- 1日の終わりは自動で確定（毎晩20:30）。手動なら **✅ 本日分を確定**

`ダッシュボード` を見れば、その日終わっているか・何が残っているかが一目で分かります。

運用フローの詳細は [`docs/03_運用フロー.md`](docs/03_運用フロー.md)。

## 4. 100店舗への展開（一元管理）

- 各店舗は**同じコード**を使い、`Config.gs` の店舗IDだけ変える
- 本部用スプレッドシートを1つ用意し、そのIDを各店の `CENTRAL_SS_ID` に設定
- 毎晩、各店から**その日1行のサマリ**（完了率・未完了数など）が本部の
  `店舗別サマリ` シートに自動で集まる
- 本部側は集計・ランキング・アラートを組める（雛形は `docs/02_マルチ店舗展開.md`）

---

## 5. なぜ「このサンドボックスから直接あなたのシートを編集」しないのか

この開発環境には、あなたのGoogleアカウントのログイン情報がありません
（安全のため渡すべきでもありません）。そのため外部から直接あなたの
スプレッドシートを書き換えることはできません。

代わりに、**スプレッドシートに紐づく GAS がシートを操作する**のが正攻法で、
これはまさに「プログラムでシートを編集する」仕組みそのものです。
この方式なら、権限はあなたの承認のもとであなたのシート内で完結します。

  Log.gs              日次ログ read/write
  Dashboard.gs        ダッシュボード生成
  Menu.gs             カスタムメニュー
  Triggers.gs         自動化トリガー（記録/朝リセット/夜確定）
  CentralSync.gs      本部集約への送信
  appsscript.json     マニフェスト
docs/
  01_導入手順.md
